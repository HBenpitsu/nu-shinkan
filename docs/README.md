ここでは，`docs`ディレクトリの運用方針を説明します．

## `docs/`直下

`docs/`直下に配置するドキュメントについては，特に制限を加えません．
ただし，サブディレクトリについて一通り確認し，整合するディレクトリがない場合にのみ`docs/`直下にドキュメントを配置してください．

また，一連のドキュメントシリーズや，一定の文脈のもとでグルーピングできるドキュメントが多数（典型的には5ファイル以上）からなる場合は，新たにサブディレクトリを作成して整理してください．

## snippets.md

実装の揺れを抑えることを目的として，仕組みとして共通化するほどではないが，頻繁に現れるコードスニペットや，記法，ボイラープレートを記入します．

## ADR/

設計判断の記録を格納するためのディレクトリです．
特に，複数の候補があり，一方を選んだ場合は，対立候補や採用理由などを記録することが望ましいです．

## discussion/

一時的なドキュメントを配置することを目的としたディレクトリです．
一時的なドキュメントとは，ある目的を達したあとには見返されることがないものを言います．
例えば，エージェントとのディスカッションや実装計画などがこれに当たります．

永続化する価値が生じた場合は，その時点でADRディレクトリや，discussionディレクトリの外部にファイルを移動させてください．

## tools/

開発用ツールの使い方や手順を説明した文書を格納するディレクトリです．
典型的には，以下のような場合に用います．

- 追加したスクリプトの使い方を説明するとき
- フレームワークを導入したときについてきたREADME.mdを退避するとき

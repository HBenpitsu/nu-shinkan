# CLIの作成方針

この文書は、コマンドラインから起動するプログラム（CLI）の構成と責務を定める。起動時の入出力と業務ロジックを分離し、それぞれを独立して理解・変更できる構造にする。現状の実装を説明するものではなく、実装が従うべき方針を示す。

## エントリーポイントの責務

各CLIに独立したエントリーポイントファイルを1つ置く。エントリーポイントは、プログラムの起動処理を置くファイルを指す。すべてのCLIを1ファイルへ統合する意味ではない。

エントリーポイントは、引数・環境変数の取得、入出力、処理の呼び出し、エラー表示・終了処理を担当する。非同期処理も含めて失敗を捕捉し、終了状態へ反映する。

## 内部ロジックとの分離

独自の選択・変換・業務上のバリデーションなど、検証が必要な複雑さを持つロジックは別モジュールに置く。内部ロジックには取得済みの値を渡す。

依存方向はエントリーポイントから内部モジュールへの一方向にする。内部モジュールはエントリーポイントをimportせず、その読み込みでCLIが起動しない構造にする。単純な入出力や転送だけの処理を、テストのためにさらに分解しない。

エントリーポイントにテスト用の `main` のexportや、`VITEST` による起動回避分岐を設けない。検証対象は[テスト方針](./testing-policy.md)に従って判断する。

具体的なファイル分離とエラー処理は[エントリーポイントの作例](./snippets/script_entrypoint.md)を参照する。

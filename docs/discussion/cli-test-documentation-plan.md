# CLI・テスト方針の文書更新計画

## 目的・状態

この文書は、CIでのCLI起動由来の不安定なテストを整理する際の文書担当者への引き継ぎである。会話を読む必要はない。ここに示す文書更新は提案であり、記載した参照文書・指示ファイルの変更は未実施。コード改修とテスト実行は別担当の作業とする。

## 確定している要求

各CLIは1つの独立したエントリーポイントファイルを持ち、引数・環境変数取得、入出力、処理呼び出し、エラー表示を担当する。このファイルをテストからimport・実行しない。業務上の選択・変換・バリデーションなど、テストが必要な複雑さを持つロジックだけを別モジュールに抽出して直接検証する。標準パーサ、単純な転送やI/O、`syncPackageLocal()` のような委譲関数をテストしない。

GitHub Workflow のテストを追加しない。YAML・シェル・Actionの代替テストも追加しない。品質上の不足があれば、既存ログの確認と必要な診断ログの追加を先に検討する。既存のプロセス起動なしのWorkflow関連テストの全面削除は要求されていない。

## 作業開始時に読むもの

リポジトリの `AGENTS.md` に従い、`docs/`、`.agents/instructions/`、`.agents/skills/` を再帰的に探索する。特に `.agents/README.md`、documentation配下の指示、`implementation-consistency.md`、`docs/snippets/script_entrypoint.md`、`docs/snippets/ts_export_for_test.md` を読む。ADRを扱う場合は `docs/ADR/AGENTS.md` と各文書の保護条件も読む。

## 更新する文書

| 文書 | 操作と内容 | 完了条件 |

| `docs/testing-policy.md`（新規） | 人間とエージェント向けの継続的な参照文書。検証対象の判断、CLIとの境界、単純関数をテストしない例、Workflowとロギングの扱い、検証方法を記載 | 会話や今回のテスト名を知らなくても、何をテストしないかと何を抽出するか判断できる |

| `docs/snippets/script_entrypoint.md`（更新） | 現在の `if (!process.env.VITEST) main()` の作例を、CLIファイルと内部ロジックファイルの分離例に置換 | CLIはテストされず、テストはロジックファイルだけをimportする。テスト用main exportやVITEST回避分岐を勧めない |

`docs/testing-policy.md` は全体方針としてdocs直下に置く。今回の3つの引き継ぎ文書は一時的な計画なので `docs/discussion/` に置く。参照文書には未実装の関数名や作業の進捗を混ぜない。

## 参照文書に含める判断例

- テストする：グラフ到達性、循環、設定の更新規則、デプロイ対象選択、未知パッケージや不正Worker名の業務上の検証。
- テストしない：parseArgs/JSON.parseの標準挙動、stdout/stderr、終了コード、stdin、引数転送、単純な保存呼び出し、ループ構造・ネストされた分岐構造を持たない15行以下の関数．Github Workflow
- Github Workflowでは，テストの代わりにロギングを充実させる．
- テストから実CLIを起動しないという方針は、テストランナー自体や本番のTurbo/CLI実行を禁止するものではない。
- 完全にモックされた外部サービス操作の再試行など、実プロセスを起動せず独自の振る舞いを検証する既存テストは維持できる。
- 一時ファイルによる設定の意味的な検証は許容する。標準I/Oの実装確認を目的にしない。
- Workflowの問題調査では、既存ログの段階・対象・終了状態・失敗理由を確認する。ログを足す場合も秘密値や設定内容を出さない。ログは事前の自動回帰検出を代替保証しない。
- 既存テストの削除によって検証しなくなる範囲を明示する。コードを別ファイルへ移しただけで、単純な処理がテスト対象になるわけではない。

## 変更しない文書と制約

`AGENTS.md` とREADMEに新規指示のindexを追加しない。保護された `docs/ADR/deploy-model.md`、`deploy-design.md`、`configuration-design.md` の仕様をテスト削除に合わせて変更しない。

`docs/ADR/workflow-script-guidelines.md` は独立mjsと関数exportについての既存判断であり、すべての関数のテストを要求してはいない。今回改訂する必要はない。ADRの既存内容の書き換えは禁止されているため、将来変更が必要になった場合はローカル指示に従う。

## 手順と検証

1. 実装側の現状と、上記の確定要求を区別して参照文書を作成する。
2. 指示ファイルと2つの作例を更新する。規則の詳細は参照文書へ寄せ、矛盾する独立した規則を作らない。
3. `rg` で `VITEST`、`testExports`、CLIテストに関するdocsと指示の記述を検索し、今回触れる作例・方針に矛盾がないか確認する。既存コードのVITEST分岐の一括撤去は文書担当の作業に含めない。
4. リンク先・Markdown構造・作例のファイル分離を確認する。文書変更のためのテストは追加しない。
5. 完了報告に更新ファイル、適用対象、保護文書を変更していないことを記す。
